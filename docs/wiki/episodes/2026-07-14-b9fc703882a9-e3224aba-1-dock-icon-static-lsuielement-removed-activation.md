# Episode: Dock icon: static LSUIElement removed, activation policy toggled at runtime

## Prior State

App's Info.plist hardcoded LSUIElement=true, pinning it as a background-only UIElement regardless of runtime NSApplication.setActivationPolicy calls. Windowed mode called setActivationPolicy(.regular) but the Dock tile never appeared.

## Trigger

User feedback that Dock icon was missing in windowed mode; debug logging confirmed setActivationPolicy returned true (now=0=.regular) but Dock registration still failed. Root cause: static LSUIElement in the build-script-generated plist overrode runtime policy.

## Decision

Removed LSUIElement from the Info.plist generated by tts-menu build script. Activation policy is now toggled dynamically: .regular when windowed mode + panel visible, .accessory otherwise, with NSApp.activate(ignoringOtherApps:) nudge to force Dock registration. Also fixed an ordering bug where panel.isVisible was checked before ordering the window front.

## Consequences

- App identity is now runtime-determined: background accessory in HUD mode, foreground app in windowed mode
- Build script no longer emits LSUIElement key; launchd/LaunchServices registration follows runtime policy
- Confirmed via lsappinfo showing ApplicationType=Foreground when windowed player is visible
- HUD mode retains accessory/background-only behavior with no Dock presence

## Open Tail

- Whether toggling activation policy repeatedly (open/close window) causes Dock tile flicker on older macOS versions
